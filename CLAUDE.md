# Фионика — как работать в этом репозитории

## Точка входа

Если фаундер пишет **«продолжаем развивать продукт»** (или просто просит взять
следующую задачу) — **прочитай `docs/RAZVITIE.md` целиком** и предложи
следующий шаг оттуда. Это единственный живой список задач: незакрытое из всех
прежних записок перенесено туда, датированные `docs/zadachi-novyi-chat-*.md` —
архив.

В конце работы **обнови `docs/RAZVITIE.md`**: отметь сделанное ✅ с номером
версии (строку не удаляй), допиши новое, запиши решения вместе с причиной и
датой. Иначе следующая сессия начнёт с нуля.

⚠️ Ничего из § 7 «Решения, которые не переоткрываются» не предлагать заново без
слова фаундера.

## Кто фаундер

Нетехнический. Перед git-действиями объясняй по шагам. Push, удаления и
изменения публичной инфраструктуры — только после подтверждения.

## Git

В этой папке **одновременно работают два чата**. Перед `git add -A`
**обязательно** смотри `git status`: чужое подготовленное к коммиту легко
утащить в свой коммит или переписать. Начиная крупный экран — скажи об этом
вслух в `docs/RAZVITIE.md`.

Цикл: правим файлы → фаундер выполняет в Терминале

```
cd ~/Documents/GitHub/kodokvest
find .git -name '*.lock' -delete
git add -A && git commit -m "описание" && git push
```

GitHub Desktop не используем — виснет на `.lock`-файлах.

## Обязательное перед коммитом

- поднять версию в `package.json` (у каждого изменения свой номер);
- `npm test` — шесть проверок, включая сверку примеров с настоящим python3;
- `npm run audit` — аудит уроков, эхо, обходы, линтер;
- собрать `dist/kodokvest.html` через `node build.js` (входит в `npm test`);
- изменение видно родителю, репетитору или ученику — запись в
  `content/novoe.json` (дата = день коммита, без счётчиков вроде «97 задач»)
  и `node tools/lenta.js`. Это лента «Что нового» на главной; сторож `[лента]`
  сверяет даты с git. Внутренние правки (тесты, разрезы кода) туда не пишем.

Проверки — не формальность: они стерегут обещания продукта (пять инструментов
в панели, отсутствие слова «списал», единственность ответа в задачах,
однофайловая сборка меньше 4 МБ — потолок поднят с 3 МБ словом фаундера 24.09.2026).

## Как писать

Продукт объясняет себя сам, и документы тоже. В доках: короткие абзацы,
таблицы, ⚠️ перед тем, что легко сломать, причина рядом с решением, дата рядом
с числом. Число без даты и ссылки — не число.

Тон интерфейса: понятность важнее скорости. Подсказка объясняет явно, пример
наглядный и не является ответом.
