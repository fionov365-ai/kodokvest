# Кодоквест

Тренажёр Python для подростков. Сто уроков от первой команды `print` до собственного проекта.
Код выполняется прямо в браузере: без установки, без интернета, без серверов.

**Готово: все 100 уроков, пять миров.** Курс закончен. Плюс разделы вне
сотни: «Сегодня» (дневной стрик со щитом и задача дня), «Игры» (5 играбельных игр),
«Разминка» (14 упражнений «угадай вывод» и «собери из блоков»), «Визуализатор»
(пошаговый разбор памяти с перемоткой и стрелками-ссылками), «Ты и ИИ»
(11 упражнений: как командовать ИИ, включая три задания «вынеси вердикт»),
«Повторить» (интервальный повтор трудных уроков) и «Шпаргалка» (справочник
на 86 команд, открывается поверх урока). В конце каждого из пяти миров —
свой проект: многошаговая программа, которую ребёнок уносит с собой.

## Как запустить локально

Просто открыть `index.html` в браузере не получится: браузер запрещает подгружать файлы
уроков с диска. Нужен любой локальный сервер:

```bash
cd kodokvest
python3 -m http.server 8000
```

Дальше открыть `http://localhost:8000`.

Либо собрать всё в один файл и открыть его двойным щелчком:

```bash
node build.js
# готово: dist/kodokvest.html
```

## Как выложить бесплатно на GitHub Pages

1. Создать репозиторий на github.com, например `kodokvest`.
2. Загрузить в него содержимое этой папки (кнопка **Add file → Upload files** или через git).
3. Зайти в **Settings → Pages**, в разделе *Build and deployment* выбрать
   Source: **Deploy from a branch**, ветка `main`, папка `/ (root)`, нажать **Save**.
4. Через минуту сайт будет по адресу `https://ИМЯ-ПОЛЬЗОВАТЕЛЯ.github.io/kodokvest/`.

Хостинг бесплатный и без ограничений по трафику для такого объёма.
Альтернативы с тем же результатом: Cloudflare Pages, Netlify — там достаточно перетащить папку в браузер.

## Прогресс на сервере

По умолчанию прогресс лежит в `localStorage` — в памяти одного браузера на одном
устройстве. Этого хватает для занятий, но посмотреть с другого устройства нельзя.

Чтобы видеть занятия откуда угодно, подключается сервер: Cloud Function в Yandex Cloud
плюс бакет Object Storage. Настройка описана по шагам в **[cloud/README.md](cloud/README.md)**,
занимает около двадцати минут и делается один раз.

Главное про устройство:

- **Прогресс сливается, а не перезаписывается.** По каждому уроку берётся лучший
  результат из двух копий, бейджи объединяются, звёзды и опыт не уменьшаются.
  Занятия с двух устройств по очереди ничего не ломают.
- **Код ученика — настройка устройства, не сайта.** У каждого ребёнка свой код,
  задаётся в панели или ссылкой `?kid=код`. Один сайт годится для нескольких детей.
- **Пока сервер не настроен, всё работает как раньше** — оффлайн, без сети,
  без единого сетевого запроса.
- При одном-двух учениках потребление укладывается в бесплатные лимиты Yandex Cloud
  целиком; разбор цифр — в `cloud/README.md`.
- Функция публичная: кто знает её адрес и код ученика, тот видит его прогресс.
  Кроме кода, звёзд и времени занятий сервер не хранит о ребёнке ничего.
  Подробный разбор рисков — в `cloud/README.md`.

## Регистрация по имени

При первом заходе (если сервер подключён, а ученик ещё не выбран) открывается
экран регистрации: ребёнок вводит имя, сайт делает из него код ученика
(`slugFromName` — транслитерация + случайный суффикс) и запоминает. Настоящих
аккаунтов с паролями нет намеренно — всё держится на существующем «коде ученика»
(`js/cloud.js`) и синхронизации, отдельный бэкенд не нужен.

- **Имя** хранится в `S.name`, едет вместе с прогрессом (в `mergeProgress`
  побеждает более свежее, но не теряется, если в свежей копии пусто).
- **Вход с другого устройства** — по коду или ссылке `?kid=код` на экране
  «Профиль» (кнопка 👤 в шапке). Там же — сменить ученика (`выйти`): забыть код на
  устройстве и очистить локальный прогресс (на сервере он остаётся).
- **Смена ученика чистит локальный прогресс** перед загрузкой чужого
  (`resetProgressLocal`), чтобы не смешать двух детей на одном устройстве.
- Функции в `app.js`: `screenRegister`, `screenAccount`, `doRegister`, `doLogin`,
  `doLogout`, `slugFromName`, `needsRegister`, `myName`, `myCode`. Гейт на старте:
  `needsRegister()` (сервер настроен и кода нет) → `screenRegister`.
- **Оговорка про безопасность:** это удобный вход, а не защита. Код лежит в
  памяти браузера и виден тому, у кого есть устройство или ссылка. Настоящие
  аккаунты с логином/паролем потребовали бы серверной авторизации, которой у
  проекта нет (и это осознанное решение — см. `HANDOFF.md`).

## Панель наставника

Служебный экран для взрослого: видно прогресс, можно открывать и зачитывать уроки.

**Как войти:** дописать к адресу сайта `admin` и ввести код. Работают три формы
(выбирай любую, что удобнее): просто `admin` в конце пути, `?admin` или `#admin`.

```
https://ИМЯ-ПОЛЬЗОВАТЕЛЯ.github.io/kodokvest/admin
https://ИМЯ-ПОЛЬЗОВАТЕЛЯ.github.io/kodokvest/?admin
https://ИМЯ-ПОЛЬЗОВАТЕЛЯ.github.io/kodokvest/#admin
```

Вариант без `#` работает благодаря файлу `404.html`: GitHub Pages отдаёт его на
адрес `.../kodokvest/admin` и он перекидывает на `?admin`. Файл нужно залить
вместе с остальными.

**Код по умолчанию:** `kodokvest-2026`. Меняется в `js/app.js`, строка `var ADMIN_CODE = ...`
в начале файла. После правки — пересобрать (`node build.js`) и перезалить сайт.

**Честно про защиту.** Сайт публичный, и код лежит в исходнике страницы: подросток,
который умеет смотреть исходный код, панель откроет. Это защита от случайного нажатия,
а не пароль. Настоящая защита требует сервера, которого у проекта нет.

**Что умеет:**

- сводка: пройдено уроков, звёзды, XP, ранг, попытки, подсказки, время за тренажёром, дата последнего занятия;
- **отчёт «Что было за неделю»** — то же самое человеческим языком: занятия и уроки
  за семь дней, полоса дней, три самых трудных урока с причинами и что дальше
  по программе (см. отдельный раздел ниже);
- если подключён сервер: состояние обмена, ручные «отправить» и «забрать», проверка настройки,
  просмотр прогресса другого ученика по его коду и список всех учеников по ключу наставника;
- таблица всех 100 уроков: звёзды, число попыток, взятые подсказки, смотрел ли решение, время, дата;
- по каждому уроку: «открыть», «зачесть» (три звезды), «сбросить»;
- «Открыть все уроки» — снимает замки, но звёзды не ставит: порядок перестаёт быть обязательным;
- выдать или отобрать бейдж, записать XP вручную, сбросить весь прогресс —
  сброс стирает звёзды, XP, бейджи, статистику, серию дней, разминки, «Ты и ИИ»
  проекты и повторы, но **оставляет** имя ученика, расписание, песочницу и свои версии
  игр: это не результат занятий, а работа ребёнка (смена ученика чистит и их);
- скачать файл прогресса и загрузить его на другом устройстве.

**Про хранение.** Без сервера прогресс лежит в `localStorage` — в памяти конкретного
браузера на конкретном устройстве, и посмотреть его с телефона нельзя. Для разового
переноса есть выгрузка файла в самом низу панели. Чтобы видеть занятия постоянно
и с любого устройства, подключите сервер — см. `cloud/README.md`.

## Как добавить урок

1. В `js/curriculum.js` найти нужный мир и убедиться, что у урока есть строка с `id`.
   **Менять существующие `id` нельзя** — по ним хранится прогресс ученика.
2. В `content/worldN.js` добавить объект с этим `id`:

```js
"my-lesson-id": {
  draw: false,              // true — если нужен холст черепашки
  lede: "Одна вводная фраза.",
  theory: [
    { h: "Заголовок", p: "Объяснение.", demo: 'print("живой пример")' },
    { h: "Ошибка как урок", p: "Этот пример должен упасть.",
      demo: 'print("7" + 3)', err: true }
  ],
  task: {
    type: "code",
    goal: "Что нужно сделать.",
    list: ["Требование раз", "Требование два"],
    starter: '# заготовка, она должна запускаться без ошибок\n',
    solution: 'print("эталон")',
    hints: ["подсказка 1", "подсказка 2", "подсказка 3"],
    check: { kind: "output" }
  }
}
```

Виды заданий (`type`):

- `"code"` — написать код по заготовке;
- `"fix"` — **найди и почини ошибку** (см. ниже);
- `"blocks"` — собрать из перемешанных строк. **Сделано, живёт в разделе
  «Разминка»** (`js/warmups.js`) — см. ниже;
- `"predict"` — угадать вывод до запуска. **Сделано, живёт в разделе
  «Разминка»** (`js/warmups.js`) — см. ниже.

Виды проверки:

- `{ kind: "output" }` — вывод ученика сверяется с выводом `solution`
- `{ kind: "output", lines: ["29"] }` — сверка с заданными строками
- `{ kind: "turtle" }` — сравнивается рисунок, а не текст кода
- `{ kind: "turtle", pen: true }` — вместе с рисунком сверяются цвет и толщина линий
- `{ kind: "custom", fn: "имя" }` — своя функция из `CUSTOM` в `app.js`
- `{ kind: "tests", calls: [...] }` — **скрытые тесты** (см. ниже)
- дополнительно `needText: ["-> str"]` — потребовать **подстроку**: нужно там, где
  «по словам» искать нельзя (стрелка в подсказке типов, тройные кавычки)
- дополнительно `needCode: ["for"]` и `needMsg` — потребовать конструкцию в коде.
  **Это обычный текст, а не регулярное выражение:** спецсимволы экранируются,
  поэтому `"max("` и `"*аргументы"` работают как есть. В многофайловом задании
  проверяются все файлы, а не только главный
- дополнительно `noCode: ["for", "while"]` и `noMsg` — **запретить** конструкцию.
  Нужно, когда решение обязано быть определённым: урок про рекурсию не должен
  проходиться циклом, а урок про `@dataclass` — ручным `__init__`

### Ответы для input()

Клавиатуры в браузере у программы нет, поэтому ответы на `input()` записываются
заранее — списком строк. Ученик видит и правит их в панели «ответы для input()»
справа и может запустить программу с другими ответами.

```js
task: {
  stdin: ["Аня", "север", "выход"],
  starter: 'print("Что делаешь?")\nкоманда = input()\n…',
  …
}
```

То же поле есть у примера теории: `theory[i].stdin`.

Правило курса: **приглашение печатаем отдельным `print()`, а `input()` вызываем
без аргумента.** У `input("текст")` приглашение печатается без перевода строки,
и в тренажёре вывод склеивается — набранного-то не видно. Эталон считается на тех
же ответах, что и код ученика, поэтому сравнение честное. Когда ответы кончились,
поднимается `EOFError` — ровно как у настоящего Python.

### Код, который показан, но не запускается

Настоящий Flask, pandas, matplotlib и команды терминала в тренажёре работать
не могут. Их показывают как есть, с честной подписью:

```js
{ h: "А как это делают на работе",
  p: "Объяснение.",
  show: 'import pandas as pd\nтаблица = pd.read_csv("оценки.csv")',
  showNote: "так это выглядит на компьютере, после pip install pandas" }
```

`show` можно ставить и вместе с `demo`, и вместо него. Карточка без `demo`
обязана иметь `show` — это проверяет `tests/lessons.js`.

### Задание из нескольких файлов

Уроки про модули и про свою библиотеку состоят из двух и более файлов.
Настоящих файлов в браузере нет, поэтому файлы урока описываются прямо в задании,
а над редактором появляются вкладки. Для ученика разницы не видно: `import tools`
работает как в жизни.

```js
task: {
  type: "code",
  mainName: "main.py",              // как назвать главную вкладку, по умолчанию main.py
  starter: 'import tools\n…',        // главный файл
  solution: 'import tools\n…',
  files: [
    { name: "tools.py",
      starter:  'def clean(text):\n    return text\n',
      solution: 'def clean(text):\n    return text.strip().lower()\n' }
  ],
  check: { kind: "output" }
}
```

Правила: имя файла — как настоящее имя модуля (`tools.py`, маленькими буквами);
`solution` у файла можно не писать, если ученик его не меняет; главный файл всегда
идёт первой вкладкой. Пример теории тоже может иметь свои файлы — поле `files`
рядом с `demo`, только там это объект `{ "tools.py": "…" }`.

### Файлы с данными

Уроки про файлы, JSON и таблицы получают готовые файлы: поле `data` у задания и
у примера теории. Файлы живут в памяти запуска — каждый запуск начинается с той же
копии, и что записала программа, видно ученику в панели «файлы на диске».

```js
task: {
  data: { "оценки.txt": "аня 5 4 5 3\nборя 3 3 4\n" },
  starter: 'with open("оценки.txt", encoding="utf-8") as f:\n    …',
  …
}
```

То же поле есть у примеров теории (`theory[i].data`). Правило: в уроках всегда
пишем `encoding="utf-8"`, а для csv ещё и `newline=""` — в тренажёре это не нужно,
но ровно так код должен выглядеть на настоящем компьютере.

### Задание со скрытыми тестами

Ученик пишет функцию по спецификации и не видит проверок — как на работе.
Каждый вызов из `calls` дописывается к его коду отдельной программой, результат
сравнивается с тем же вызовом на эталонном решении.

```js
check: { kind: "tests", calls: [
  'initials("иван петров")',
  'initials("")'
] }
```

Проверки идут по порядку, ученику показывается первая непройденная — какой вызов,
что должно было вернуться и что вернулось. В `calls` обязательно включать неудобные
случаи (пустая строка, ноль, один элемент): именно на них и учат смотреть.
Тест `lessons.js` требует, чтобы заготовка эти проверки НЕ проходила, иначе задания нет.

### Задание «найди и почини ошибку»

```js
task: {
  type: "fix",
  goal: "Что программа должна делать.",
  symptom: "Что сейчас не так — это ученик видит в красной карточке.",
  list: ["Найди и исправь одну ошибку", "Остальной код не переписывай"],
  starter: 'total = sum\nprint(totl)',      // сломанный код
  solution: 'total = sum\nprint(total)',    // как должно быть
  hints: ["…"],
  check: { kind: "output", fixBudget: 2 }
}
```

Отличия от обычного задания:

- `starter` — **сломанный** код. Он обязан работать неправильно: либо падать, либо давать
  не тот результат. Тест это проверяет и не даст залить урок, где чинить нечего.
- `symptom` обязателен: ученик читает описание симптома, а не гадает.
- в редакторе появляется кнопка **«↩ Вернуть как было»**.
- проверка следит, чтобы код **чинили, а не переписывали**. Считается разница между
  заготовкой и работой ученика в «единицах»: переписать строку = 2, добавить или убрать = 1.
  Если правок больше `fixBudget`, урок не зачитывается — даже когда вывод правильный.
  По умолчанию `fixBudget` = разница между `starter` и `solution` плюс 1.
  Практика: если у задания есть короткий обходной путь («выкинуть сломанную строку»),
  ставь `fixBudget` вручную и добавь этот путь в список `BYPASS` в `tests/full-run.js`.

## Раздел «Сегодня»: дневной стрик, задача дня, расписание и щит

Отдельный экран (кнопка «🔥 Сегодня» в шапке, адрес `#today`), вне сотни уроков,
звёзд и XP не даёт. Смысл — привычка заходить каждый день.

- **Дневной стрик** — сколько дней подряд ребёнок занимался. Считается не
  счётчиком, а по множеству дат в `S.days` (строки `"ГГГГ-ММ-ДД"` по местному
  времени). Такой способ устойчив к переводу часов и к слиянию устройств:
  синхронизация — это просто объединение множеств дней. День засчитывается за
  любое полезное действие: пройденный урок (`winLesson`) или решённую разминку
  (`winWarmup`, включая задачу дня). Текущий стрик, рекорд и полоска за неделю —
  функции `streakCurrent`, `streakBest`, `weekStripHTML` в `app.js`.
- **Задача дня** — одна разминка на день, **детерминированно** выбранная из уже
  проверенного пула `js/warmups.js` по хэшу даты (`dailyPick`). Поэтому на всех
  устройствах в один день задача одна и та же, каждый день новая, и **сервер для
  этого не нужен**. Выполнение отмечается в `S.daily["ГГГГ-ММ-ДД"]`.
- Открывается задача дня тем же движком разминок: `openWarmup(id, { daily:true })`.
  Флаг `daily` меняет навигацию (назад ведёт на «Сегодня») и финал (огонёк,
  «Задача дня выполнена», текущий стрик).
- **Расписание занятий.** На том же экране «Сегодня» ребёнок отмечает дни недели,
  когда планирует заниматься (`S.schedule.days` — номера дня недели как у
  `getDay()`, 0=Вс…6=Сб). В учебный день появляется напоминание **только внутри
  сайта**: баннер на «Сегодня», отметка 📌 в недельной полоске и колокольчик на
  кнопке 🔥. Расписание — это настройка, а не результат, поэтому при синхронизации
  побеждает более свежее сохранение (в `mergeProgress`), а не объединение —
  иначе снятый на одном устройстве день возвращался бы с другого. Функции в
  `app.js`: `scheduleDays`, `isStudyDay`, `toggleStudyDay`, `studyDue`.

- **Щит для стрика** — один пропущенный день не обнуляет серию. Щиты **не хранятся
  счётчиком**: в `S.shields` лежит множество ДАТ, на которые щит потрачен, а сколько
  щитов заработано — вычисляется из числа дней занятий (`SHIELD_EVERY` = 5 дней на
  щит, в запасе не больше `SHIELD_MAX` = 2). Оба множества сливаются объединением,
  поэтому на любом устройстве получается один и тот же ответ. Серия считается по
  «закрытым» дням: занимались ИЛИ день закрыт щитом (`coveredDays`). Функции в
  `app.js`: `coveredDays`, `shieldsLeftIn`, `shieldToNextIn`, `shieldWouldSave`,
  `useShield`, `shieldBoxHTML`, `takeShieldNote`.
- **Бейджи за длинный стрик** — `week` (7 дней подряд) и `month` (30 дней подряд),
  список `STREAK_BADGES` в `app.js`. Щит держал серию, а награды за неё не было:
  ребёнок видел растущее число и всё. Порогов два, потому что один достижимый
  сразу, а второй остаётся целью. Проверяются в двух местах: в `markActiveToday`
  (день засчитан здесь) и в `applyProgress` (серия доросла на другом устройстве —
  бейдж должен быть уже тут, а не ждать следующего занятия). Серия считается по
  «закрытым» дням, поэтому месяц не требует тридцати занятий без единого пропуска.
- **Когда щит срабатывает.** Не в полночь, а в момент, когда ребёнок вернулся и
  что-то сделал (`markActiveToday` → `useShield`): статический сайт не может
  выполнить код, пока он закрыт, — та же причина, по которой напоминания живут
  только внутри сайта. Заодно это честнее: щит награждает возвращение, а не
  отсутствие. Пока ребёнок не сел заниматься, серия показывает 0, поэтому экран
  «Сегодня» отдельно пишет «щит наготове» (`shieldWouldSave`), иначе выглядело бы
  так, будто всё пропало.
- **Щит закрывает ровно ОДИН день** и только если позавчера серия была: пропустил
  два дня подряд — серия честно начинается заново. Закрытый день виден щитом 🛡
  в недельной полоске, а запас — блоком под ней.

**Грабли:**

- **Стрик держится на `S.days`, а не на числе.** Не заводи отдельный счётчик,
  который надо инкрементировать, — он разъедется при слиянии двух устройств.
  Множество дат сливается объединением и всегда даёт верный результат.
- **Даты для арифметики берём в полдень** (`key + "T12:00:00"`): сдвиг на день
  через `setDate` тогда не перепрыгивает сутки при переходе на летнее время.
- **`S.days` и `S.daily` добавлены в `mergeProgress`** (объединение) — иначе
  занятия с другого устройства рвали бы стрик. `S.days` ограничен ~800 днями
  (`pruneDays`), чтобы не рос без предела.
- **Задача дня берётся из проверенного пула разминок** — своего непроверенного
  контента не добавляем: вывод разминок уже сверен с python3.
- **Щиты тоже множество дат, а не счётчик.** Соблазн завести `S.shieldCount` и
  уменьшать его — та же ошибка, что и со стриком: два устройства офлайн разъедутся.
  Хранится только `S.shields` (даты, на которые щит потрачен), запас вычисляется.
  Крайний случай слияния: оба устройства офлайн потратили последний щит на РАЗНЫЕ
  дни — после объединения потрачено на один больше, чем заработано. Ничего не
  ломается (запас уходит в ноль и восстанавливается занятиями), и оба спасённых дня
  остаются закрытыми — так честнее к ребёнку.
- **`S.shields` обязан быть в `mergeProgress` (объединение), в `resetProgressLocal`
  и в обоих сбросах панели наставника.** Забудешь — спасённые дни то появятся, то
  пропадут при синхронизации.
- **Расписание сливается «свежее побеждает», а не объединением.** Это набор,
  который редактируют (дни снимают), поэтому union вернул бы снятый день с другого
  устройства. `S.schedule` добавлен в `mergeProgress` через `fresher`/`older`.
  Напоминания — только внутри сайта (баннер, полоска, колокольчик): статический
  сайт сам ничего не пришлёт, когда он закрыт.

## Раздел «Разминка»: угадай вывод (predict) и собери из блоков (blocks)

Отдельный раздел рядом с «Играми» (кнопка «Разминка» в шапке, адрес `#warmup`).
Это **не входит в сотню уроков**. Два вида упражнений, оба в `js/warmups.js`,
различаются полем `type`:

- **`type: "predict"`** — ребёнок читает готовую программу и до запуска пишет,
  что она напечатает. Потом сверка: правильно — маленькая победа, нет — видно
  настоящий вывод и где именно разошлось.
- **`type: "blocks"`** — строки программы перемешаны, ребёнок собирает их обратно
  (перетаскиванием или кнопками ▲ ▼). Отступы у строк зафиксированы и служат
  подсказкой о вложенности — их менять нельзя, только переставлять строки целиком.

Зачем отдельно: сотня уроков жёстко устроена как «5 миров по 20», нумерация и
прогресс завязаны на это. Разминки живут своим списком в `js/warmups.js`, их
прогресс хранится в `S.warmups` (объединяется при синхронизации, но **звёзд и
XP не даёт** и в счётчик «пройдено из 100» не попадает).

Как добавить разминку — просто ещё один объект в массив `window.WARMUPS`:

```js
{
  id: "predict-loop",          // менять нельзя: по нему хранится «разгадано»
  type: "predict",
  title: "Сумма в цикле",
  emoji: "🔁",
  tag: "циклы",                // короткая метка темы на карточке
  intro: "Одна завлекающая фраза.",
  brief: "Что напечатает программа? Запиши по строкам.",
  code: 'total = 0\nfor n in range(1, 5):\n    total += n\n    print(n, total)\n',
  hints: ["намёк", "сильнее", "почти разгадка"],
  note: "Объяснение, которое видно после верного ответа — учит, а не пересказывает."
}
```

Для `blocks` те же поля, только `type: "blocks"`, а `code` — это **правильный
порядок строк**. При открытии строки перемешиваются; пустые строки в блоки не идут.

```js
{
  id: "blocks-sum",
  type: "blocks",
  title: "Сумма из цикла",
  emoji: "🔢",
  tag: "циклы",
  intro: "Одна строка должна оказаться внутри цикла.",
  brief: "Собери программу, которая сложит числа и напечатает сумму.",
  code: 'total = 0\nfor n in [4, 7, 2]:\n    total += n\nprint(total)\n',
  hints: ["намёк", "сильнее", "почти разгадка"],
  note: "Почему такой порядок — а не пересказ строк."
}
```

Правила и грабли (проверяются тестами):

- **`code` — источник правды.** Для `predict` верным считается вывод программы;
  для `blocks` — любой порядок, дающий такой же вывод. В обоих случаях программа
  обязана запускаться без ошибок, что-то печатать и совпадать с python3.
  Никакой случайности, времени и черепашки.
- **`blocks`: ответ должен быть единственным.** Проверка идёт по выводу, поэтому
  следи, чтобы КАЖДАЯ содержательная строка влияла на результат. Иначе тренажёр
  примет логически сломанную сборку (так уже ловилось: функция с `if`, у которой
  тестовый вызов не задевал одну из веток, — пришлось печатать два вызова).
  Нужно ≥3 строк, иначе собирать нечего.
- **Сравнение снисходительно к хвостам:** хвостовые пробелы в строках и пустые
  строки в конце не важны. Поэтому упражнения, весь смысл которых в хвостовых
  пробелах, сюда не кладём.
- **Нужна настоящая ловушка/задача.** Если ответ очевиден с первого взгляда —
  упражнения нет. И следи, чтобы `intro`, `brief` и первая подсказка не выдавали
  ответ заранее; хинты должны объяснять «почему», а не диктовать готовый порядок.
- **`note` объясняет «почему», а не печатает «что».** Пересказ ответа — плохой note.

## Раздел «Визуализатор»: машина времени

Отдельный раздел (кнопка «Визуализатор» в шапке, адрес `#viz`), вне сотни уроков,
прогресс не хранит. Ребёнок пишет или выбирает пример, жмёт «Показать по шагам» —
программа прогоняется, и на каждом шаге снимается состояние памяти. Дальше можно
листать историю **вперёд и назад** ползунком, автопроигрывать, и видеть:

- текущую строку кода (подсвечена);
- переменные и объекты — списки, словари, кортежи, множества — нарисованными
  коробками с ячейками;
- **стрелки-ссылки**: когда две переменные показывают на один объект (`b = a`),
  от обеих идёт стрелка к одной коробке, одним цветом, и в шапке коробки написаны
  оба имени. Так `b = a` перестаёт быть загадкой — видно, что список общий;
- **что изменилось на этом шаге** — полоской над памятью и подсветкой самой
  изменившейся ячейки;
- **стек вызовов** — когда программа заходит в функцию, её переменные показаны
  отдельной коробкой поверх коробки главной программы.

### Что изменилось на шаге

Ползунок показывал состояние, но не изменение: ребёнок листал кадры и сам искал
глазами, что стало другим. На словаре из восьми ключей это работа «найди
отличия», а не понимание. `vizDiff(prev, cur)` в `app.js` сравнивает соседние
кадры и делает две вещи: **говорит фразой**, что произошло («вызвана функция
`площадь(ш = 3, в = 4)`», «`всего`: 0 → 12», «в словарь добавился ключ `'м'`»,
«напечатано: 22»), и **помечает** изменившееся — золотая рамка у нового,
бирюзовая у изменившегося (`vzn` / `vzc`). Метка ставится на саму ячейку, а не на
всю коробку: в словаре из восьми ключей важно, какой именно поменялся.

Считается изменение всегда **относительно предыдущего кадра**, а не относительно
того места, откуда прыгнули ползунком — иначе «на этом шаге» значило бы разное в
зависимости от того, куда ребёнок ткнул на шкале. И то же правило, что у живого
разбора расхождения: молчать, если сказать нечего — полоска просто скрывается.

### Стек вызовов

`heapSnapshot` раньше сваливал все области видимости в один список и
дедуплицировал имена. Внутри функции это врало: ребёнок видел местную `ш` и
никак не мог узнать, что внешняя `ш` с другим значением всё ещё существует —
а это ровно то место, где новички путаются.

Теперь `Interp` ведёт `this.stack` — `[{name, env}]`, снизу вверх (счётчика
`this.depth` для этого не хватало: он знает глубину, но не имена и не местные
переменные кадров). Стек пишется в `push`/`pop` вокруг вызова функции, на
выполнение не влияет — это наблюдение, а не механика. `stepper().next()` отдаёт
его копию, а `heapSnapshot(env, idMap, skip, stack)` добавляет к снимку
`scopes` — по списку переменных на каждый кадр. Куча (`objects`) при этом одна на
весь снимок, как и в настоящем Python.

Пока программа в функции не заходила, кадр один — и рисуется как раньше, без
рамки и заголовка: чрома не должно быть больше, чем данных. Имя функции в
заголовке кадра **не переводится в верхний регистр** (в отличие от подписи
«главная программа»): в Python имена регистрозависимы, и `ПЛОЩАДЬ` — это другое
имя, подпись не должна врать про код.

Обратный путь рекурсии наш шагомер по одному вызову не показывает: он выдаёт шаг
на каждую СТРОКУ, а возвраты из вложенных вызовов случаются внутри одного
выражения `n * факториал(n - 1)`. Поэтому стек сворачивается сразу на несколько
кадров, и разбор честно говорит сколько, а не называет один.

Остальное внутри:

- В движке (`js/engine-mini.js`) есть `heapSnapshot(env, idMap, skip, stack)` —
  снимает **неизменяемый** снимок: переменные + все контейнеры с идентичностью
  объектов. `idMap` (общий на прогон) держит соответствие «объект → id», поэтому
  один и тот же список получает один id на всех шагах — так и рисуется алиасинг.
- Грабля: словарь в движке — это `Map`, где значение это пара `[настоящий_ключ,
  значение]`, а ключ Map закодирован (`keyOf`). В снимке берём именно пару, иначе
  ключи покажутся как `'s:м'` вместо `'м'`.
- Вся отрисовка и плеер — в `js/app.js` (`screenViz`, `vizRecord`, `vizPlayer`,
  `vizMemoryHTML`, `vizScopeHTML`, `vizDiff`, `vizDrawArrows`). Стрелки рисуются SVG поверх по реальным
  координатам; если геометрии нет (скрытый блок, тест в jsdom) — стрелки молча
  пропускаются, а цвет и имена в шапке всё равно показывают связь.
- Кадры ограничены (`VIZ_MAX_FRAMES`), длинную программу показываем частично.

## Раздел «Ты и ИИ»: как командовать ИИ

Отдельный раздел (кнопка «Ты и ИИ» в шапке, адрес `#ai`), **вне сотни уроков**,
прогресс в `S.ailab` (звёзд и XP не даёт). Одиннадцать упражнений про три навыка,
которые ИИ не забирает: точно ставить задачу, читать чужой код и проверять
результат. **ИИ сценарный** — «ответ ИИ» это заранее написанный нами код прямо
в упражнении, живую модель не зовём. Судья правды — сам движок: он запускает
«код от ИИ» и показывает, где тот падает или врёт. Полная педагогическая заметка
и содержание — в `docs/ai-module.md`.

Внутри — гибрид уже существующих механик. У каждого упражнения поле `type`:

- **`predict`** — прочитай код и до запуска напиши вывод. Как в «Разминке»:
  открывается `makePredictStudio`, правильный ответ — это вывод программы `code`.
- **`code`** — напиши код по заготовке. Как в уроках: `makeStudio`, сверка вывода
  с выводом `solution`.
- **`fix`** — сломанный «код от ИИ», найди и почини одну поломку. Тоже `makeStudio`,
  плюс бюджет правок `fixBudget` (переписать всё заново нельзя). Урок про
  «выдуманную функцию» специально падает с ошибкой — поэтому он `fix`, а не
  `predict` (там программа обязана запускаться).
- **`review`** — вынеси вердикт. Единственный тип, где ребёнку **не говорят
  заранее**, сломан ли код: он читает, запускает, подставляет свои данные и
  сам решает. Подробно — ниже.

Диспетчер и проверки — в `js/app.js`: `screenAILab` (витрина), `openAILesson`
(открыть упражнение), `runAIPredict` / `runAICheck` / `wireReview` (проверка),
`winAI` (финал). Контент — в `js/ailab.js` (`window.AILAB`).

### Тип `review`: вынеси вердикт

Остальные три типа говорят ребёнку ответ до того, как он начал: тип `fix` так и
называется — «почини», значит код точно сломан. `review` этой подсказки не даёт.
Ребёнок видит код от ИИ и его обещание (`claim`), может запускать и переписывать
код как угодно — студия тут лаборатория, а не задание, — и выбирает один из трёх
вердиктов:

| Вердикт | Что значит |
|---|---|
| `ok` | делает обещанное на любых данных |
| `partly` | на своём примере верно, на других врёт |
| `wrong` | расходится с обещанием на своём же примере |

Три ответа, а не два, — потому что «врёт сразу» и «работает, но не всегда» это
разные вещи, и вторая как раз про код от ИИ: он почти всегда сходится на том
примере, который показан вместе с ним. После верного вердикта `partly`/`wrong`
надо ещё **ткнуть в строку** с поломкой (`badLine`) — угадать с трёх кнопок можно,
а с трёх кнопок и десятка строк уже нет. Ответ `ok` засчитывается сразу: там
поломки нет, и признать это — тоже работа проверяющего.

**Правильный ответ не записан, а вычисляется.** У записи есть `truth` —
правильная версия с тем же интерфейсом и тем же примером, — и `probe`, несколько
своих проверок, которые дописываются и к `code`, и к `truth`. Дальше вердикт
выводит `reviewTruth()` в `app.js`, запуская четыре программы:

```
вывод code ≠ вывод truth               → wrong   (врёт на своём же примере)
выводы совпали, а с probe разошлись    → partly  (не всегда)
совпали и там, и там                   → ok      (работает верно)
```

Поле `verdict` в содержании — та же величина, записанная руками; игра судит по
вычисленной, а `tests/lessons.js` считает её сам и падает, если содержание
разошлось с запуском. `badLine` тоже не берут на слово: тест выводит его из
разницы между `code` и `truth` и требует, чтобы расходилась ровно одна строка —
иначе у ребёнка было бы несколько правильных ответов. Соврать в задании такого
типа нельзя: правду говорит движок.

После победы карточка показывает **доказательство** (`reviewProof`) — на каких
именно данных код разошёлся с обещанием.

```js
{ id: "ai-...", type: "review", title: "...", emoji: "⚖️", tag: "выносим вердикт",
  intro: "...", brief: "...",
  claim: "что ИИ обещает — одной фразой",
  code:  `... код от ИИ вместе с его собственным примером ...`,
  truth: `... правильная версия: тот же интерфейс, тот же пример ...`,
  probe: `print(функция(другие_данные))
`,   // дописывается и к code, и к truth
  verdict: "partly",                          // тест сверит с запуском
  badLine: 6,                                 // при ok — не указывать
  hints: ["...", "..."],
  note: "разбор, виден только после победы" }
```

Как добавить упражнение — ещё один объект в массив `window.AILAB`:

```js
// predict — прочитать и предсказать вывод
{ id: "ai-...", type: "predict", title: "...", emoji: "🤖", tag: "читаем код",
  intro: "...", brief: "...", hints: ["...", "..."],
  code: `x = 5\nprint(x * 2)\n`,        // правильный ответ — вывод этой программы
  note: "разбор, виден только после победы" }

// fix — починить сломанный код (или code — написать по заготовке)
{ id: "ai-...", type: "fix", title: "...", emoji: "🐞", tag: "проверяем и чиним",
  intro: "...", brief: "...", list: ["требование 1", "требование 2"],
  symptom: "что сейчас не так (для fix)",
  starter: `... сломанный код ...`,      // fix: обязан работать НЕ так, как solution
  solution: `... рабочий код ...`,       // задаёт правильный вывод
  fixBudget: 2,                          // сколько правок максимум (для fix)
  needCode: ["sum("], needMsg: "...",    // опц.: требуемые конструкции
  hints: ["...", "..."],
  note: "разбор, виден только после победы" }
```

Правила (их проверяют тесты, см. `tests/`): у `predict` программа `code` обязана
запускаться, что-то печатать и совпадать с python3; у `code`/`fix` то же для
`solution`; у `fix` заготовка обязана быть сломана, решение отличается на 2–8
правок, а `fixBudget` не меньше этих правок; у `review` с python3 сверяются все
четыре программы (`code`, `truth` и обе с `probe`), вычисленный вердикт обязан
совпасть с записанным, а `truth` — не быть дословной копией `code`. **Новый файл в разделе подключается
в трёх местах:** `index.html`, список `scripts` в `build.js` и `eval(...)` в
`tests/lessons.js` и `tests/content-vs-python.js`.

## Проект в конце мира

Отдельная штука рядом с уроками: **многошаговое задание, где все шаги строят одну
и ту же программу**. Смысл — момент «я собрал целую вещь», которую видно и можно
показать. Содержание — в `js/projects.js` (`window.PROJECTS`), по одному проекту
на мир. Готовы все пять:

| Мир | Проект | Что собирается | На чём стоит |
|---|---|---|---|
| 1 | 🃏 Карточка героя | генератор карточек персонажа | строки, циклы, функции, `if` |
| 2 | 🏆 Турнирная таблица | таблица лиги с местами и разницей мячей | словари, `sorted` с `lambda`, множества, включения |
| 3 | 🎒 Рюкзак героя | система вещей с правилами | классы, наследование, `raise`/`except`, `assert` |
| 4 | 📜 Чёрный ящик | разбор журнала сервера | регулярки, `Counter`, генератор, декоратор, JSON |
| 5 | 🌐 Свой сайт | мини-фреймворк: маршруты, страницы, 404 | функции как значения, словари, шаблон |

Проект Мира 5 закрывает дыру, которую иначе не закрыть: уроки про Flask
(`web-1`…`web-4`) в браузере запустить нельзя, и веб оставался для ребёнка
разговором. Здесь он своими руками пишет то, что Flask делает внутри —
словарь «путь → функция», коды ответа, общий шаблон, — и всё это работает.

Устройство:

- **Код переезжает из шага в шаг.** Стартовый код шага N+1 — это то, что ребёнок
  написал на шаге N (`projectStartCode`); если своего кода нет, берётся эталон
  предыдущего шага. Поэтому в конце получается цельная программа, а не четыре
  отдельные задачки.
- **Вне сотни уроков:** звёзд и XP не даёт, в счётчик «N из 100» не входит.
  Прогресс — `S.projects[id] = { step, code, done }`, где `step` это номер текущего
  шага (он же количество пройденных). За первый собранный проект даётся бейдж
  «🏗 Строитель».
- **Но карточка проекта показана прямо на карте мира**, сразу за последним уроком
  (`.projcard` в `screenWorld`) — иначе раздел вне сотни легко пропустить.
  Открывается, когда все готовые уроки мира пройдены (либо включено «Открыть все
  уроки» в панели наставника).
- **Финальный экран** (`screenProjectDone`) показывает программу целиком, её можно
  запустить и забрать кнопкой «Забрать в песочницу» (кладёт код в `S.sandbox`).
- Функции в `app.js`: `projectsList`, `projectById`, `projectOfWorld`,
  `projectState`, `projectOpen`, `projectStartCode`, `openProject`,
  `runProjectCheck`, `winProjectStep`, `screenProjectDone`.

Как добавить проект — ещё один объект в `window.PROJECTS`:

```js
{
  id: "project-w2",          // менять нельзя: по нему хранится прогресс
  world: 2,
  emoji: "🎲",
  title: "Название",
  tagline: "одна строка: что это за программа",
  intro: "зачем и что получится в конце",
  steps: [
    { title: "Шаг", brief: "что сделать", list: ["требование", "требование"],
      starter: "...",        // обязателен ТОЛЬКО у первого шага
      solution: "...",       // ПОЛНАЯ программа на конец этого шага
      needCode: ["def "], needMsg: "...",
      hints: ["...", "...", "..."] }
  ],
  finale: "текст на финальном экране"
}
```

Правила (проверяются тестами):

- `solution` каждого шага — **полная** программа на конец шага; она обязана
  запускаться, что-то печатать и совпадать с python3;
- **вывод каждого шага обязан отличаться от вывода предыдущего** — иначе шаг
  ничего не добавляет и это не шаг;
- заготовка первого шага обязана **запускаться** (ребёнок жмёт «Запустить» и видит
  работающую, пусть и неполную, программу) и **не проходить проверку**;
- у шагов 2+ `starter` не пишется вовсе: туда переезжает код ребёнка;
- в проекте можно пользоваться только тем, что объяснено в этом мире и раньше;
- новый файл подключается в **трёх** местах: `index.html`, список `scripts`
  в `build.js` и `eval(...)` в `tests/lessons.js` и `tests/content-vs-python.js`.

## Раздел «Повторить»: работа над ошибками

Урок, который дался тяжело, забывается первым — а тренажёр про это ничего не знал,
хотя данные копил с самого начала. В `S.log` по каждому уроку лежат `attempts`,
`hints`, `shown` и `solvedAt`; раньше они только показывались в панели наставника.

Как это работает:

- **Кто сюда попадает.** Не «нерешённое» — нерешённых уроков в разделе не бывает.
  Сюда попадает пройденное, которое стоило дорого: показанное решение, взятые
  подсказки, три и больше попыток (`REVIEW_HARD`) или неполные звёзды. Причина
  называется словами прямо на карточке («решение было показано», «подсказок: 2»).
- **Когда зовёт.** Промежутки расширяются: `REVIEW_STEPS = [2, 7, 21]` дней.
  Отсчёт — от последнего повтора, а если его не было, от `solvedAt`.
- **Чем кончается.** Три чистых повтора подряд — урок «закреплён» и больше не
  просится. Сбился (подсказка, вторая попытка, показанное решение) — счётчик
  обнуляется, урок вернётся послезавтра. За пять закреплённых — бейдж «🔁 Закрепил».
- **Повторяют то же самое задание.** Отдельных задач на повтор не пишется: смысл
  в том, чтобы вспомнить, как это делается, а не решить новое. Звёзды при этом
  только растут (`winLesson` не понижает уже полученные) — хуже, чем было, не станет.
- **Хранение:** `S.review = { "id-урока": { n, at } }`, где `n` — сколько раз
  закреплён. Поле в `PROGRESS_MAPS`, при слиянии с сервером берётся больший `n`.
- Функции в `app.js`: `reviewState`, `reviewWhy`, `reviewDueAt`, `reviewList`,
  `reviewDue`, `reviewGraduated`, `reviewAfterLesson`, `screenReview`, `reviewNote`.
  Адрес раздела — `#again`, кнопка в шапке показывает число созревших уроков.

## Шпаргалка

Справочник на 86 команд: `js/cheatsheet.js` (`window.CHEATSHEET`), девять групп —
от «Вывод и текст» до «Модули и данные».

Два решения, которые стоит помнить:

- **Это оверлей, а не экран.** Шпаргалка чаще всего нужна посреди урока, а уход
  со страницы урока стирает написанный код (черновики нигде не сохраняются).
  Поэтому она открывается поверх (`#sheet`, `hidden`), и на это есть тест: он
  проверяет не «объект жив», а что `#studio` остался в документе с содержимым.
- **Вывод примеров нигде не хранится** — его считает движок в момент показа
  (`sheetRun`, с запоминанием на время сессии). Значит, справочник физически
  не может разойтись с тем, что ребёнок получит у себя. Тесты при этом сверяют
  каждый пример с настоящим python3.

Показывается только пройденное (по `lesson` каждой записи); галочка «показать всё»
открывает остальное, отметив его как «ещё не проходили». Есть поиск по сигнатуре,
описанию, коду и названию группы. Закрывается по Esc, по крестику и по клику мимо окна.

Запись выглядит так:

```js
{ id:"join", sig:'"разделитель".join(список)', lesson:"text-work",
  what:"склеивает список строк в одну строку. Обратное к split",
  code:'print(", ".join(["кот", "ёж", "сова"]))' }
```

`lesson` обязан быть настоящим id урока из `curriculum.js` — это проверяет тест.
Примеры не должны трогать черепашку, ввод с клавиатуры и файлы; случайность можно
(пример со случайным числом честно печатает разное, сверка с python3 его пропускает).

в данных нет, нельзя.

Блок показывается и для своего прогресса, и в режиме просмотра чужого (с сервера).

## Живой разбор расхождения

Когда код **падает**, объяснение уже есть и оно хорошее: движок свой, он видит
настоящую ошибку и говорит про неё по-русски с номером строки («После «for»
нужно двоеточие», «В списке всего 2 элемент(ов), а ты просишь номер 5»).

А когда код **не падает, а просто отвечает не то**, ребёнок до недавнего получал
только две колонки «должно быть / получилось» и номер строки вывода. Что именно
не так — ни слова. В самом злом случае — лишний пробел на конце — колонки
выглядели **одинаково**, и ребёнок сидел над двумя как бы совпадающими текстами.

`whyDiffer(exp, got, emptyWhy)` в `app.js` называет разницу словами. Разбор один
на всё приложение: его звинчивают и `diffBlock` (уроки, «Ты и ИИ», проекты), и
`predictDiff` (разминки, «угадай вывод»), поэтому новый случай появляется сразу
везде. Что он опознаёт:

| Случай | Что говорит |
|---|---|
| разница только в пробелах и табах | называет, где именно (конец строки, начало, двойной пробел, таб) — **и показывает их значками**: пробел `·`, таб `→` |
| разница только в регистре | «Буквы все на месте, разница только в заглавных» |
| те же строки, другой порядок | какая строка стоит не на своём месте |
| строк меньше, чем надо | а если первые совпадают — «не хватает последних, их печатают ПОСЛЕ цикла, без отступа» |
| строк больше, чем надо | а если нужные идут первыми — «печать попала внутрь цикла и повторилась» |
| `2` против `2.0` | «Целое и дробное — разные вещи: / всегда даёт дробное, // — целое» |
| числа отличаются на единицу | «нумерация с нуля или range, который до последнего числа не доходит» |
| напечатан сам список/словарь | «нужны значения по отдельности: пройди циклом или собери через join» |
| значение в кавычках | печать `repr(...)` вместо самой строки |
| запятая как десятичный разделитель | «В Python дробная часть отделяется точкой» |
| ничего не напечатано | текст задаёт вызывающий: у урока «программа не напечатала», у разминки «ты ничего не написал» |

**Главное правило — молчать, если не уверены.** Пустой ответ разбора это норма:
тогда остаётся прежняя механическая подсказка про номер строки. Ложное
объяснение хуже отсутствующего — оно уводит от настоящей причины. Поэтому в
`tests/full-run.js` проверяются обе стороны: и что причина названа верно, и что
на непохожих ответах разбор ничего не выдумывает.

## Что умеет встроенный движок

Переменные, числа с разделением int и float, строки и f-строки, списки, словари, кортежи,
срезы, `if/elif/else`, `for`, `while`, `break`, `continue`, `def` со значениями по умолчанию,
распаковка (`a, b = ...`), около 40 встроенных функций, методы строк, списков и словарей,
черепашья графика.

Ошибки выдаются по-русски, с номером строки и объяснением причины.
Есть защита от бесконечных циклов.

Добавлено во второй волне: **множества** (литералы, `set()`, методы, операторы `| & - ^`),
**списковые, словарные и множественные включения** с несколькими `for` и `if`,
**`lambda`**, **`sorted(key=...)`** и `list.sort(key=...)`, **цепочки сравнений**
(`0 < x < 10` — с однократным вычислением середины, как в Python), `shuffle`, `random`, `sample`.

Добавлено в четвёртой волне (Мир 4):

- **файлы**: `open` с режимами `r`/`w`/`a`, `read`, `readline`, `readlines`,
  `write`, `writelines`, `close`, перебор файла циклом, `encoding` и `newline`;
- **`with`** — свой контекстный менеджер через `__enter__` и `__exit__`;
- **генераторы**: `yield`, `yield from`, `next`, `StopIteration`, ленивый перебор
  в `for` (бесконечные генераторы работают, в список не собираются);
- **свои декораторы** — замыкания и вложенные функции уже работали, добавилось
  `функция.__name__`;
- **модули стандартной библиотеки**: `json` (`dumps`/`loads`/`dump`/`load`,
  `ensure_ascii`, `indent`), `csv` (`reader`, `DictReader`, `writer`),
  `datetime` (`date`, `datetime`, `timedelta`, `strftime`, сравнение и вычитание),
  `collections` (`Counter` с `most_common`, `defaultdict`), `itertools`
  (`count`, `cycle`, `repeat`, `chain`, `islice`, `product`, `permutations`,
  `combinations`), `re` (`search`, `match`, `fullmatch`, `findall`, `sub`, `split`,
  группы), `pathlib` (`Path`, `/`, `name`, `stem`, `suffix`, `parent`,
  `read_text`, `write_text`, `with_suffix`), `statistics`, `time`;
- **старое форматирование строк** через `%` — в новом коде не нужно, но в чужом
  встречается постоянно;
- `int()`, `float()`, `bool()` без аргументов, `repr` с экранированием переводов

Пока не поддерживает: `while/else` внутри `try`, срезы у генераторов,
асинхронность, целые числа больше 2^53, `help()` и большую часть стандартной
библиотеки за пределами перечисленного. pandas, Flask, `requests` и git
внутри браузера не работают в принципе — Мир 5 разбирает их устройство,
а настоящий код показывает через `theory[i].show`.

Что было исправлено в третьей волне (расхождения, найденные тестами):

- `"абв".isalpha()` возвращал `False` — в JavaScript `\w` это только латиница;
- `{x:02d}` печатал `« 5»` вместо `«05»`: заполнение нулями не поддерживалось;
- `round(2.5)` давал 3, а Python даёт 2 — он округляет половинки к ближайшему
  чётному. Считать через умножение на 10 в степени нельзя: у 2.675 двоичное
  значение чуть меньше половины, поэтому разбираем десятичную запись как строку;
- `return a, b` без скобок не разбирался вообще;
- функция читала внешнюю переменную, которой ниже присваивают — Python на это
  отвечает `UnboundLocalError`, а движок молча брал внешнюю.

Известные расхождения с настоящим Python:

- **Объект без `__repr__`.** Настоящий Python печатает `<__main__.Dog object at 0x7f…>`
  — адрес в памяти повторить нельзя, у нас будет `<__main__.Dog object>`. Правило
  проекта: в уроках у класса всегда определён `__repr__`, а такие примеры не
  добавляются в корпус сверки.
- **Целые числа больше 2^53** считаются неточно: это JavaScript, целых без границ
  в нём нет. Поэтому `math.factorial` отказывается работать выше 20!.
- **Печать функции.** `print(double)` в Python показывает адрес в памяти
  (`<function double at 0x7f…>`) — повторить нельзя. В уроках печатаем `type(x)`.
- **Текст `UnboundLocalError`** в разных версиях Python разный, поэтому `str(e)`
  для этой ошибки в уроках не печатается.
- **Порядок элементов множества.** Совпасть тут не может ни один движок: настоящий Python
  выдаёт разный порядок при каждом запуске программы (хеши строк рандомизируются), а
  `{10, 200, 3000, 7}` печатает как `{200, 10, 3000, 7}`. У нас порядок вставки — предсказуемый,
  но столь же произвольный. Поэтому правило для уроков: множество печатаем только через
  `sorted()`, и в уроке про множества это объясняется прямо.

## Проверка

Пять проверок. Все сразу — одной командой из корня проекта:

```bash
npm install     # один раз, ставит jsdom для третьей проверки
npm test        # прогоняет все три подряд и останавливается на первой упавшей
```

По отдельности:

```bash
node tests/engine-vs-python.js   # движок против настоящего python3
node tests/try-one.js файл.py    # служебное: сверить одну программу вручную
node tests/lessons.js            # уроки: решения, заготовки, примеры
node tests/content-vs-python.js  # содержание уроков против настоящего python3
node tests/cloud-function.js     # сервер: запись, чтение, отказы, защита от обхода пути
node build.js && node tests/full-run.js   # игра целиком в браузерном окружении
```

1. **`engine-vs-python.js`** — программы из `tests/programs.txt` прогоняются через `python3`
   и через `engine-mini.js`, вывод должен совпасть символ в символ. Нужен установленный `python3`.
   Корпус пополняется при каждом расширении движка — сейчас в нём 149 программ.
   Строка `#!stdin: текст` внутри программы задаёт ответ для `input()`: он уходит
   и на вход `python3`, и в движок.
   Программы, создающие файлы, запускаются во временной папке, а не в проекте.
2. **`lessons.js`** — для каждого урока: решение работает; заготовка обычного задания
   работает, а заготовка задания «починить» обязательно сломана; примеры теории работают,
   а помеченные `err: true` обязательно падают; `check.lines` совпадает с выводом решения;
   есть непустые `hints` (кнопка «Подсказка» стоит на каждом уроке, и показывать ей
   должно быть что).

   запускается без ошибок и что-то печатает. Плюс схема шпаргалки: поля заполнены,
   id не повторяются, `lesson` указывает на существующий урок, а пример запускается
   и что-то печатает — иначе ребёнок открыл бы справочник и увидел ошибку.
   Плюс схема раздела «Ты и ИИ» — и у
   типа `review` не только схема: вердикт **вычисляется** запуском `code` против

   имя, зарегистрированное в `runtime.js` (список тест читает из самого файла).
3. **`content-vs-python.js`** — то же самое, но не на отдельном корпусе, а на **содержании
   уроков** (сейчас 702 сверки, включая 14 разминок, 11 заданий «Ты и ИИ», 20 шагов

   движок. Уроки из нескольких файлов проверяются по-настоящему: файлы кладутся во временную
   папку, и `python3` импортирует их с диска. Скрытые тесты сверяются тоже — каждый вызов из
   `calls` прогоняется на эталоне и там, и там. Программы разминок сверяются тоже: их вывод —
   это правильный ответ ребёнку, он обязан совпасть с python3. У заданий `review`
   сверяются все четыре программы (`code`, `truth` и обе с `probe`): вердикт

   Примеры шпаргалки сверяются по той же причине: ребёнку их показывают как «вот так
