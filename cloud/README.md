# Сервер прогресса: настройка в Yandex Cloud

Здесь лежит `index.js` — весь сервер целиком, один файл без библиотек.
Он хранит прогресс учеников в бакете Object Storage и отдаёт его по запросу.

Пока сервер не настроен, тренажёр работает как обычно: прогресс лежит
в браузере ребёнка. Сервер нужен только чтобы видеть занятия с другого устройства.

Настройка занимает минут двадцать и делается один раз. Ниже — по шагам,
ровно то, что нажимать.

---

## Сколько это стоит

Устройство сервера выбрано так, чтобы платить было почти не за что:

- **Cloud Functions.** Первый миллион вызовов в месяц и 10 ГБ×час выполнения — бесплатно.
  Один ребёнок делает примерно 2–3 тысячи вызовов в месяц, то есть до бесплатной границы
  далеко в любом случае.
- **Object Storage.** Бесплатно каждый месяц: первый гигабайт хранения, первые
  10 000 операций записи (PUT, POST, PATCH, LIST) и первые 100 000 операций
  чтения (GET, HEAD, OPTIONS). Входящий трафик и удаление не тарифицируются.
  Один ученик при получасе занятий в день делает примерно 2 тысячи записей в месяц —
  то есть впятеро меньше бесплатного предела. Прогресс весит килобайты, гигабайт
  не кончится никогда.

Итого при одном-двух детях потребление целиком укладывается в бесплатные лимиты.
Но две оговорки. Первая: бесплатный объём считается **на платёжный аккаунт**, а не
на проект — если к тому же аккаунту привязаны другие ваши облака, счётчик общий.
Вторая: Yandex Cloud требует платёжный аккаунт с привязанной картой, даже когда
потребление попадает в бесплатные лимиты.

## Шаг 1. Бакет для данных

1. Откройте [консоль Yandex Cloud](https://console.yandex.cloud), выберите свой каталог.
2. Сервис **Object Storage** → **Создать бакет**.
3. Имя — любое свободное, например `kodokvest-progress`.
4. **Доступ на чтение объектов** и **доступ к списку объектов** оставьте **ограниченным**.
   Это важно: бакет должен быть закрытым. Наружу данные будет отдавать функция, а не бакет.
5. Класс хранилища — **стандартное**. Создать.

## Шаг 2. Сервисный аккаунт

1. Сервис **Identity and Access Management** → **Сервисные аккаунты** → **Создать**.
2. Имя, например `kodokvest-fn`.
3. Роль — **`storage.uploader`**. Именно uploader: `storage.viewer` даёт только чтение,
   и прогресс не сможет записаться.
4. Создать.

## Шаг 3. Функция

1. Сервис **Cloud Functions** → **Создать функцию**. Имя, например `kodokvest-progress`.
2. Откроется редактор. Среда выполнения — **Node.js** (берите самую свежую в списке).
3. Способ загрузки — **Редактор кода**.
4. Создайте файл с именем **`index.js`** и вставьте в него **всё содержимое** файла
   `cloud/index.js` из этого репозитория. Целиком, от первой строки до последней.
5. **Точка входа** — `index.handler`. Ровно так, с точкой.

## Как обновить функцию потом

Если в репозитории поменялся `cloud/index.js` (например, в списке учеников
появилось имя), сайт об этом не узнает сам — функция живёт в облаке отдельно.
Обновление занимает минуту и делается руками:

1. Консоль Yandex Cloud → **Cloud Functions** → функция `kodokvest-progress`.
2. Вкладка **Редактор** → **Создать версию** (кнопка справа сверху).
3. В файле `index.js` выделить всё и вставить свежее содержимое
   `cloud/index.js` из репозитория. Целиком.
4. Проверить, что точка входа осталась `index.handler`, таймаут и переменные
   окружения на месте (они переносятся из прошлой версии сами).
5. **Создать версию**. Через несколько секунд работает новая.

Прогресс учеников лежит в бакете, а не в функции, — обновление его не трогает.

## Шаг 4. Параметры функции

В блоке **Параметры** того же редактора:

- **Таймаут** — 10 секунд.
- **Память** — 128 МБ.
- **Сервисный аккаунт** — тот, что создали на шаге 2.

Ниже, в **переменных окружения**, добавьте две:

| Имя | Значение |
|---|---|
| `MOUNT_POINT` | `progress` |
| `ADMIN_KEY` | придумайте длинный ключ, например `nastavnik-9d4f2ba7` |

`ADMIN_KEY` — это пароль для списка всех учеников. Он нужен только вам, вводится
в панели наставника вручную и **не хранится в файлах сайта**. Придумайте его посложнее.

## Шаг 5. Монтирование бакета

Это главный шаг: благодаря ему функция видит бакет как обычную папку и обходится
без ключей доступа и библиотек.

1. В редакторе функции раскройте **Дополнительные настройки**.
2. Блок **Смонтированные бакеты** → **Добавить бакет**.
3. Заполните:
   - **Точка монтирования** — `progress` (ровно то же слово, что в `MOUNT_POINT`);
   - **Бакет** — созданный на шаге 1;
   - **Папка** — оставьте пустой.
4. Опцию **Только чтение** обязательно оставьте **выключенной**, иначе прогресс
   не сможет записаться.
5. Нажмите **Сохранить изменения**. Создастся новая версия функции.

## Шаг 6. Открыть функцию наружу

1. Перейдите на вкладку **Обзор** функции.
2. Включите **Публичная функция**. Без этого браузер не сможет её вызвать.
3. Скопируйте **ссылку для вызова** — вид примерно такой:
   `https://functions.yandexcloud.net/d4e1a2b3c4d5e6f7g8h9`

## Шаг 7. Проверка до подключения сайта

Вставьте в адресную строку браузера ссылку функции, добавив в конец `?op=ping`:

```
https://functions.yandexcloud.net/ВАША-ССЫЛКА?op=ping
```

Должно ответить примерно так:

```json
{"ok":true,"dir":"/function/storage/progress","students":0,"adminKeySet":true,
 "hint":"Бакет смонтирован и доступен на запись — всё готово."}
```

Если `"ok":false` — смотрите поле `error` и раздел «Что может пойти не так» ниже.
Дальше идти можно только после `"ok":true`.

## Шаг 8. Подключить сайт

1. Откройте файл `js/cloud-config.js` и впишите ссылку функции в поле `url`:

```js
var CLOUD_CONFIG = {
  url:  "https://functions.yandexcloud.net/d4e1a2b3c4d5e6f7g8h9",
  code: ""
};
```

Поле `code` можно не заполнять — код ученика задаётся на устройстве, см. шаг 9.

2. Пересоберите один файл: `node build.js`
3. Залейте на GitHub изменённые `js/cloud-config.js` и `dist/kodokvest.html`
   (а если сервер подключается впервые — то и `js/cloud.js`, `js/app.js`, `index.html`).

## Шаг 9. Код ученика

Код — это имя, под которым прогресс лежит на сервере. У каждого ребёнка свой.
Кто знает код, тот видит и меняет прогресс, поэтому не делайте его угадываемым:
не `misha`, а `misha-7f3a`.

Задать код можно двумя способами:

- **В панели.** На устройстве ребёнка откройте сайт с `#admin`, введите код доступа,
  в карточке «Сервер» впишите код в поле и нажмите «Записать код».
- **Ссылкой.** Откройте на устройстве ребёнка один раз адрес
  `https://ВАШ-САЙТ/kodokvest/?kid=misha-7f3a` — код запомнится, а из адреса исчезнет.

Код живёт в памяти браузера, в файлах сайта его нет. Поэтому один и тот же сайт
годится для нескольких детей: у каждого свой код на своём устройстве.

## Шаг 10. Убедиться, что работает

На устройстве ребёнка: панель → карточка «Сервер» → **Проверить настройку**,
затем **Отправить сейчас**.

На своём устройстве: панель → карточка «Сервер» → в поле «код» введите код ребёнка →
**Посмотреть**. Должна открыться его таблица уроков в режиме только чтения.

Если детей несколько: введите `ADMIN_KEY` в поле «ключ наставника» и нажмите
**Список всех учеников** — покажет всех сразу.

## Как это устроено

Один адрес, разные операции в параметре `op`:

| Запрос | Что делает |
|---|---|
| `GET ?op=ping` | проверка: доступен ли бакет на запись |
| `GET ?op=load&code=КОД` | отдать прогресс ученика |
| `POST ?op=save&code=КОД` | записать прогресс (тело запроса — JSON) |
| `GET ?op=list&key=КЛЮЧ` | список всех учеников кратко, только по `ADMIN_KEY` |

Прогресс лежит в бакете простыми файлами `КОД.json`.

**Слияние вместо перезаписи.** Тренажёр не «затирает» прогресс: при обмене по каждому
уроку берётся лучший результат из двух копий, бейджи объединяются, звёзды и опыт
не уменьшаются. Поэтому кнопка «Забрать с сервера» безопасна, и занятия с двух
устройств по очереди ничего не ломают.

Время и число попыток при слиянии берутся **по максимуму, а не складываются**: после
первого же обмена обе копии становятся одинаковыми, и сложение удваивало бы цифры
при каждой следующей синхронизации.

Снятые замки («Открыть все уроки») на сервер не уходят — это настройка устройства.

## Что честно сказать про защиту

Функция публичная, значит:

- **Кто знает адрес функции и код ученика — читает и пишет его прогресс.** Адрес лежит
  в файлах сайта и виден любому. Единственный секрет — код ученика. Поэтому он должен
  быть случайным, и его не надо нигде публиковать.
- **Худшее, что может случиться** — постороннему станут видны звёзды и время занятий
  ребёнка, либо он их испортит. Никаких других данных о ребёнке сервер не хранит:
  ни имени, ни почты, ни возраста — только код, который придумали вы.
- **Список всех учеников** закрыт ключом `ADMIN_KEY`, и этот ключ в файлах сайта
  не хранится: вы вводите его в панели, он остаётся в памяти вкладки.
- Функция ограничивает размер записи 200 килобайтами и строго проверяет код ученика,
  так что подсунуть путь вроде `../../` и записать файл в другое место нельзя —
  на это есть тест.

Для семейного тренажёра этого достаточно. Для продукта на многих пользователей —
нет: там нужны настоящие аккаунты, согласие на обработку данных ребёнка и всё,
что к этому прилагается.

## Что может пойти не так

**`?op=ping` отвечает `"ok":false` и `EROFS` или `EACCES`**
Либо в монтировании включена опция «Только чтение», либо у сервисного аккаунта
роль `storage.viewer` вместо `storage.uploader`. Проверьте оба места.

**`?op=ping` отвечает, что папка не читается (`ENOENT`)**
Точка монтирования и переменная `MOUNT_POINT` не совпадают. Оба значения должны
быть одним и тем же словом — по умолчанию `progress`.

**Браузер показывает 403 при обращении к функции**
Не включена **Публичная функция** на вкладке «Обзор».

**В панели «Сервер недоступен»**
Проверьте адрес в `js/cloud-config.js`: он должен начинаться с `https://` и не иметь
ничего после идентификатора функции. И убедитесь, что сайт перезалит и открыт
с жёсткой перезагрузкой (в Safari `Cmd+Option+R`).

**«Список отключён: в настройках функции не задан ADMIN_KEY»**
Переменная окружения `ADMIN_KEY` не добавлена или функция не пересохранена после её
добавления. Переменные применяются только к новой версии функции.

**Прогресс не уходит сам**
Проверьте, что в карточке «Сервер» указан код ученика. Без кода отправка не работает.
Отправка идёт не чаще раза в 25 секунд — это сделано намеренно, чтобы не гонять сеть.

## Проверка кода сервера без облака

Функцию можно прогнать локально: вместо смонтированного бакета подставляется
временная папка через переменную `DATA_DIR`.

```bash
node tests/cloud-function.js
```

Проверяется запись и чтение, отказ на негодные коды и попытки обхода пути,
ограничение размера, закрытый список учеников. Плюс `tests/full-run.js` прогоняет
всю цепочку целиком: браузерный код → подменённый `fetch` → настоящая функция →
временная папка.
